# C 定向复核原文

## 首次复核

输入为 [05 草稿原文](05-draft-design.txt)与[06 草稿原文](06-draft-implementation.txt)，身份见 A 复核记录。范围：设计 §8 与实施 §3、5；执行者与最初 C 相同；只读。

已处置：§8 明确保留 v1 严格成功 **2/8**、有效复用 **4/25**，不追认旧运行分数；v2 在运行前冻结 25 个机会及 E，同时报告 M/25、M/E。真复用正控、dummy call、复制函数体、错误来源和行为失败负控，以及 unknown 不计通过、先校准再做 off/on 的顺序都已写入。P0–P3 设有 go/no-go；§3 要先做 P0，§5 声明本轮未运行新 runtime 用例，§8 声明暂无新分数或收益结论，没有把计划写成已验收事实。

剩余问题：

- **C5 P1：provider 调用边界未定。** §3 的“provider-only 成品 tools/list”、`client version/protocol`、取消清理，以及 §5 的“未配置不创建进程”，倾向于 cycle 内部 gateway；但 `discover/read` 也可理解为宿主分别暴露 provider 工具，由模型把结果交给 cycle。两者会改变实际工具面、进程归属和结果来源证明。请明确选一条路径。若宿主直连，只有宿主关联的真实调用/响应凭据才能把结果列为已观测；模型转述应保持 reported，不计入 M。若内部 gateway，则写明固定启动配置、请求绑定、取消和终态合同。不要同时实现两套。
- **C6 P1：目标覆盖意图基本写入，但关键不变量还可更直白。** P1 的“目标分类、写前拒绝、D 与目标 lineage”，REUSE-03 的“未覆盖源目标/伪豁免无副作用”，及 REUSE-04 的“未知类型按 source”已针对上一轮指出的旁路。建议再明确：enabled 模式下每个实际写入目标都必须由当前 D 覆盖；只有明确文档白名单可豁免；`implementation_targets` 只是说明目标，不能决定豁免。REUSE-03 应明确加入“实际目标未列入 `implementation_targets`”仍拒绝的样例。
- **C7 P2：M/E 的计数规则尚未形式化。** 当前已冻结机会与适用性，但未定义 E=0 的报告方式，以及合规扩展何时计入 M。建议将 M 定义为有行为或副作用证据证明其对结果有贡献的 reuse/extend；E 为预先冻结的 eligible 机会数；不适用项仍计入固定的 25 分母但不计入 E；E=0 时 M/E 报 N/A。必要新实现单列，不进入 M。
- **C8 P2：clone 负控范围偏窄。** §8 明列复制函数体负控，但没有说是否覆盖仅改名、格式化或轻微改写的克隆。建议冻结至少一个这类校准样例；若评分器无法可靠区分语义克隆，标 unknown，不把它算作有效复用。

P0–P3 的阶段门与“当前未验收”表述整体清楚；以上是补齐接口选择和评分细则后，才能按文档判定通过的剩余项。

## 最终定向复核

输入为补强后的设计 §2、8 与实施 §2、5，最终文档身份在本轮交付检查固定。

确认 **C5–C8 已处置，本轮没有剩余阻断**：

- **C5：**设计 §2 和实施 §2 明确选定 Cycle 内部 gateway，模型不直连 provider；请求绑定、缓存隔离、协议核验、取消和终态均有归属。MCP client 是否可用仍是 P0 实测门槛，不再是架构选型歧义。
- **C6：**REUSE-03 明确覆盖实际源码目标未列入 `implementation_targets` 仍拒绝，并验证拒绝发生时 pending 和产品字节不变；文档豁免及 discovery scope 另有 REUSE-04 约束。
- **C7：**设计 §8 定义 E 为预先冻结的适用机会数，M 只计有贡献证据的 reuse/extend；E=0 报 N/A，不适用机会仍留在 25 分母，必要 new 单列。REUSE-12 也要求同时报 M/25 与 M/E。
- **C8：**原样、改名/格式化和轻微改写 clone 都进入校准；无法可靠判别的克隆和未知动态贡献不计通过。

这些仍是验收计划，不是已实现或通过：实施 §2 标明新路径目前不存在，§5 标明未运行新 runtime 用例，P0–P3 也没有通过记录。本轮仅核对文档，未运行测试、模型或插件。
