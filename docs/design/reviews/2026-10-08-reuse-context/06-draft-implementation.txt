| owner / 范围 | 复用与最小改动 | 直接消费者 / 验证 |
| --- | --- | --- |

| Cycle core owner | contracts/config 加 rev2；新 `src/local/reuse-evidence.mjs` 负责 D 区块解析、来源重读与 lineage；CycleCore 的 basis/view/next/preflight/perform/QA 快照消费同一投影 | 七工具、CLI、runtime、QA worker、tests/helpers；v1 无 provider 路径与原恢复套件 |
| Gateway owner | 新 `src/adapters/component-provider.mjs`，固定启动/协议能力、query/read/recall、完整输出 SHA、超时/取消/终态/缓存副作用归档 | cycle_artifact discover/read；使用已有 runner/进程清理与 Store 原语，不能把 check passed 字段当 provider 成功 |
| Host/Skill owner | runtime/server/hook 传输观测 session；有界 emitter 与独立最小投递账本；插件 Skill 增加按需复用参考；packager 同步入口 | native package/TUI、Hook fixture；不复制 SoL ContextSessions，不改全局规则/安装源 |
| Eval owner | 独立 blog-reuse-v2 映射/贡献判断/负控/报告，复用原 fixture 和外部检查入口 | benchmarks/blog、blog-score；blog-eval-v1 评分实现/报告冻结，先校准后模型调用 |

## 3. 分期、完成标准与失败门

| 阶段 | 交付 | go / no-go |
| --- | --- | --- |
| P0 接线验证 | 隔离 slop 工作区：真实 provider-only 成品 tools/list + manifest、源/缓存写边界、取消清理；实测 Hook/MCP session 对应和 ack 有无；client 版本/协议 | 必要路径验证才开启对应能力。完整 SoL 混入、秘密读取、无法收齐源 manifest、终态不明均 no-go；无 ack 使用设计的 unknown/debounce，不假装送达 |
| P1 证据与门禁 | rev2/v1 读取兼容；discover/read/D prepare/attach；目标分类、写前拒绝、D 与目标 lineage、同 request 恢复 | 缺/伪造/过期记录在 pending 前拒绝；有效 reuse/extend/new 可推进；自身受管修改不永久卡住；未知效果不重放 |
| P2 Hook 与 QA | session 路由、预算与有限去重、Skill 最小入口、固定 checks 与冻结 QA 交接 | 未配置只读、双聊天不串线、Hook 丢失仍门禁、未知副作用优先、说明原文与 I 判词分离 |
| P3 宿主与评测 | 隔离 CODEX_HOME/TUI 装配；v2 正/负控校准；预算与标准冻结后 off/on | 实际工具面/Hook 有事实；dummy/clone 不能通过；之后才跑八题重复对照，保存原 v1 分 |

先做 P0，证据和合同可行后实现 P1/P2；不先启用两个全量插件。若无可用 provider，旧未启用项目继续原模式，启用且需查询的源码写入保留 blocked/unavailable。没有宿主 session 对应时只给通用 Hook 指针；不拿模型提供的 session_id 或 cwd 猜测任务。

## 4. 关键实现步骤

1. **发现**：验证操作者固定发行身份/协议 → 受控 peer → query 原字节+完整 manifest → Cycle 独立重读 SHA → 归档 immutable 证据。选定接口、实现、直接调用方按需读取；遗漏与动态关系显式标出。prepare/read 显示捕获、视图和未确认交付三种状态。
2. **决定**：D 唯一 `cycle-reuse-v1` 区块 → 严格 JSON/Zod → 精确 targets/选择/理由/原始 evidence refs → prepared handle。attach 复核正文与 refs。只保存投影，不维护另一本 reuse.json；文本语义保持 reported。
3. **写入**：原授权/绑定 → 真实目标分类 → D/来源/策略当前性 → expected_sha256 → pending → Workspace.apply → 已观察文件效果 → outcome/settle。shared/registry/已记录调用方修改标 needs_refresh；消费者目标依已知 cursor 继续；外部变化不能自动吸收。
4. **提醒**：从本地状态生成枚举摘要 → semantic fingerprint → session/epoch 路由及有限 debounce → 按优先级移除字段 → 最终 UTF-8 序列化字节检查。账本独立短 lease，不复用长检查/写入租约；锁/缓存错误不使业务状态改变。Stop 仍空返回。
5. **验证**：真实 source/调用方与 D 前后快照 → 项目固定 check_ids → 独立 QA 冻结输入。保留 I 实现说明供维护，但不将其判词交给 QA；新约束必须进入受影响 QA/checks basis，不能沿用旧 Q 宣告通过。

禁止把“已捕获/已返回”写成“模型已读懂”，把静态 export/import 写成动态调用证明，或把 provider cache 归档成功写成产品任务完成。

## 6. 升级、失败恢复与回退

先配对交付 provider-only 与 cycle rev2 能力，显式启用项目配置，再在临时安装验证；不自动改现有全局插件或宿主信任。新产物包含原生成器的安全边界，版本仅在用户要求发布时调整。

准备/查询失败：保留原 D/旧观测但标 stale/unavailable，不改产品。产品 partial/unknown：沿原 operation 检查实际前/后/第三态并显式恢复，不能重跑。Hook 账本损坏：给最小指针，不假造 ack；只在已配置辅助目录安全重建路由数据，工程证据不删除。

关闭新能力须由操作者显式配置，并对启用中的 cycle 保留原固定策略；先按原授权结束/放弃后再开始旧模式。不能让模型通过关开配置获得绕过。回退不删除旧 source/operation/QA/benchmark 证据，也不以 git reset/clean 还原用户内容。
