# Hook + MCP + Skill 工程循环：待评审设计 v0

本文件是方案草案，不是已实现能力、已确认安装目标或运行证明。读 facts.md 核对原始资料与已通过证据。最终归属待用户答复，接口和分期可由评审修正。

## 目标与非目标

在当前授权范围内运行 R→D→实现/I→独立QA/Q→缺陷修复或Delta，保留真实状态与恢复点；仅关键用户决定升级给用户。机械规则在核心/MCP边界检查，Skill提供语义与工程判断，Hook不重复塞入全文指南。

不新建完整PRD、通用工作流DSL、云调度平台或全语言代码分析器；不宣称Hook覆盖所有工具，不以程序验证证明QA语义，不自动commit/push/部署/长期唤醒。

## 责任与数据流

拟定四层：

1. **Skill**：恢复原主控、补目标与验收、技术取舍、拆分实施、安排独立QA、裁决发现；按MCP返回的当前缺项行动，文档不成为运行时状态副本。
2. **MCP适配**：公开有界操作/错误/证据引用，验证输入、接入宿主取消、调用同一核心。可用工具按项目显式模式启用，不每轮注册所有可选组件分析。
3. **Hook适配**：SessionStart/恢复给阶段和缺项；受支持PreToolUse检查当前绑定与范围；Stop仅提示可执行收尾且限制继续次数。Hook失败或工具旁路不能伪造后端完成。
4. **工程核心**：唯一cycle状态、不可变工件/证据、版本与操作身份、租约、变更/批准关联、完成条件。Hook/MCP都是调用者，不各自写独立业务状态。

执行/存储/QA宿主能力通过窄接口接入。core不依赖MCP连接，不直接生成Prompt或解析任意Shell命令；模型调用/Host操作属于adapter，需明确能力与权限。

## 与 codex-sol 的关系：两个待裁决落点

**独立插件**：独立产品名称、周期领域与Skill，codex-sol参考/可选复用基础能力。不能直接依赖 ../codex-sol/src 私有路径或发布时复制整套协调器。真实复用可经已有MCP作为明确的执行/证据provider，或先建立稳定的共享核心包接口；任何涉及codex-sol改动/发布须后续实施授权。现有组件索引保持可选。分发前必须解决依赖可用性和版本绑定，不能称尚未发布的core库已经可用。

**codex-sol可选扩展**：同一runtime中显式启用cycle模式，复用现有store/records/validation/write/lease，增加领域协调与Skill。保持既有4/6/13模式输入输出和完成语义，默认关闭新能力。cycle完成与现有change完成须明确映射；不能新增两个可同时写同一工作区的owner或让两个协调器各自判同一任务完成。组件复用部分不得成为无登记项目的强制前提。

待评审重点：哪条复用路径最小且确实可分发？cycle领域与现有ChangeCoordinator的关系应如何表达，既不复制通用基础能力，也不强行泛化现有组件业务。

## 状态与权威

- **外部权威**：已有需求/设计/决定/蓝图，按原主控适配，保留原ID与历史。核心保存引用、版本与获准增量，不另建第二份PRD。
- **R/D工件**：从权威来源捕获的有版本契约与决策引用，包含用户原场景、范围、非目标、验收与兼容约束。
- **I工件**：当前实际实现、模块/调用方、公开理由、偏差、不变量、已知问题、验证边界和下一步；与实际源码身份绑定。模型可以提交说明，不可填造程序执行事实。
- **Q证据**：不可变验收输入manifest、执行者/宿主观测、检查与发现、原始运行回执；独立性、证据当前性、语义判定分列。
- **Delta**：proposed/approved/incorporated/rejected/deferred，含旧/新、来源、影响和批准引用；incorporated仅表示权威契约同步，代码/验证另记。
- **Cycle指针**：当前R/D/I/Q版本、活动工作/操作ID、当前阶段、绑定scope/权限、阻塞、记录同步状态和下一安全动作。它不是新的需求正文。

状态可以表示 planning / implementing / verifying / reconciling / completed / interrupted / abandoned；blocked为有明确原因的进展状态，不覆盖真实副作用。文档-only/只读任务有独立动作范围，批准R2不授予本轮实现权。完成是核心派生条件，不接受模型直接提交completed=true。

Cycle指针更新使用期望版本；工件追加不可变，旧Q保留历史。执行前保存operation_id与pending，执行事实、归档事实和结算事实分开；不因exit_code=null重放。受影响输入改变使相关Q失效。持久化只使用项目local存储，秘密与隐藏Prompt不进入工件。

## 拟定公共操作（名称/数量待评审）

按职责而非阶段模板暴露最少能力：

- 打开/观察/显式恢复当前cycle：读取既有来源，关联当前范围与已知授权，更新使用expected version；status不跑runner。
- 准备/提交职责工件：prepared manifest绑定cycle/role/来源/输出契约；submit仅接受结构、来源和当前性，不表示任务通过。
- 受管写入：显式paths及patch/full-write，绑定cycle/version/动作权限；目录、安全校验与实际写入在同一租约下再次检查，含move两端。
- 实际验证：只运行项目配置的固定argv检查，保存原始输出/退出/环境与输入身份；复用旧证据需核对相关条件。
- QA工作：start/status/result或外部受信验收导入；异步模型工作期间释放工作区租约，使用冻结输入，完成后重新核对当前输入。
- Delta reconciliation：建议、批准证据引用、权威写回确认；不得让“我是用户批准的”字符串变成批准。
- 完成：核对必要工件、当前Q、必要检查、原目标覆盖、记录同步及未解决项，先归档完整证据再发布completed。

响应至少返回cycle binding、实际阶段/缺项、证据身份、下一允许动作、coverage/未证实部分。大输入/输出有预算与handle精确召回，不把全部历史注入模型。

## 独立 QA 与授权：待验证的 Host 契约

拟定 **HostEvidenceAdapter**，提供可核实的执行身份、parent/child关系、起始输入manifest、工作终态与输出引用。宿主可提供可信客户端可见证据时，核对QA不同于实现actor、无继承实现历史的起始输入、冻结源码/原需求及实际运行；不根据model传入role/fresh_context=true判verified。

有独立执行身份但不能核对起始输入时，分别记录identity observed/context unverified，不能合并成完整独立QA。拿不到关键观测时返回QA_VERIFICATION_UNAVAILABLE，保留可完成的本地检查；若本轮要求独立QA，该条件未满足，不能静默降成自审通过。

尚未确认可实现的具体宿主适配入口。需要首先做能力PoC：用实际可用的Codex调用/日志/API在授权范围观测，不调用不存在的SDK、不捕获隐藏请求。插件宿主的自带指令与被审查用户资料有不同可信来源，只有公开可见的输入部分能声明已核实。

批准类似处理：需要可核对的用户决定/本轮任务范围来源，不能仅信模型表单字段。无法核实的目标改变保持proposed/待确认。项目允许人工导入决定时来源和可信等级明确，不能把模型自行导入当用户批准。

## 核心不变量与失败

1. 原需求失败修实现；新目标单独Delta；未批准变更不替换基线。
2. 除只读报告外，所有受管操作有明确cycle/期望version/范围/动作权限，禁止凭“当前工作区”继承另一会话任务。
3. 程序事实来自实际执行/观测；模型工件中事实声明保留reported来源，不能变成已验证回执。
4. QA当前性依赖R/D/源码/测试/配置与关键环境身份；Hash只证明内容身份，不证明QA正确。
5. 完成前再次核对输入；归档或发布失败留unfinished，已执行效果保存，不自动重放。
6. Hook只覆盖已验路径；受管后端二次校验；旁路修改靠快照检出，不能宣称操作从未发生。
7. 只读/文档-only/实施范围分别限制；候选下一轮不能自行扩范围。
8. 阻塞/中断允许带真实未完成状态退出；只对可执行收尾有限续跑，不无限Stop循环。
9. 权威记录同步未完成不能说“完整闭环完成”；重新恢复先核对现状而非重播事件。

## 分期与可判定验收

**P0 Host/复用PoC**：确认最终落点与真实可分发复用边界；验证客户端可见QA身份/首次输入/终态能获取到哪一级，以及Hook实际覆盖。做可行/不可行分支，不拿文档当宿主证明。

**P1 最小闭环**：单工作区/单活动可写cycle、原契约来源映射、R/D/I/Q/Delta引用与快照、受管write/verify、status与恢复；默认需要的独立QA保证必须由P0已验adapter提供，否则明确未就绪。

**P2 语义/增量与宿主收尾**：fresh QA实际委派和回传、缺陷/新需求分流、批准/同步凭证、Stop提示、Skill薄化；验证完整的一轮与下一轮已授权增量。

必测场景：已有docs/design及历史I错误；范围越界/跨任务/旧版本；QA后source变化且HEAD未变；QA字段伪造/同actor/输入污染；批准需求但文档-only；原标准未过而提议放宽；取消/副作用已发生但归档失败；完成发布前漂移；Hook不可用/未连接MCP/旁路Shell；无JS登记的Python或纯文档项目；旧SoL4/6/13模式不变（若扩展该项目）。

选项目既有测试与隔离真实宿主试验，提供反例→观察结果→修正验收的映射；不以工具个数、结构校验或单次模型通过证明稳定自主工程效果。
